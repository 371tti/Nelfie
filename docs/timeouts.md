# タイムアウト方針

タイムアウトは処理ごとの責務に合わせて設定します。ユーザー応答の期限は準備から生成までを一つの期限で扱い、Discordへの最終送信と進捗表示には独立した短い期限を設けています。個別の上限と、期限切れ後の動作は次のとおりです。

| 処理 | 上限 | 期限切れ時の動作 |
| --- | ---: | --- |
| ユーザー・cron 応答の準備とモデル生成 | `timeout_millis`（現在100秒） | 実行中の生成 future と進捗タスクを止め、エラー表示を最大5秒で試みる |
| Discord添付URLの更新 | 1応答あたり15秒 | 更新できていない古い画像URLを会話履歴から外し、画像なしで応答生成へ進む |
| 応答の最終送信（本文・添付・画像） | 1応答あたり30秒 | 進捗表示または modal にエラーを最大5秒で通知する。すでに送れた分は残る場合がある |
| 進捗更新・失敗・rate limit 通知 | 1操作あたり5秒 | ログに記録して処理を終了する。通知のために応答タスクを止め続けない |
| Discord HTTP通信 | 1 HTTPリクエストあたり30秒 | Serenity のリクエストが失敗する。rate limit 待ちなどを含む上位操作の期限は各処理側で別途制限する |
| コンテキスト要約 | `timeout_millis`（現在100秒） | 未完了batchを反映せず終了する。timeout前に反映済みのbatchは履歴に残る |
| VOICEVOX音声合成 | 1テキスト segment あたり45秒 | その読み上げ処理をエラーで終了する。長文全体の所要時間は segment 数に応じて増える |
| VOICEVOXキューへの空き待ち | 2秒 | キュー満杯エラーを返す |
| 音声 segment の再生処理 | 30秒 | 音声処理をエラーで終了する。並列再生は track 終了待ちを含み、逐次再生はキュー投入を上限にする |
| 音声辞書のページ操作 | 14分 | component collector を終了し、ボタンを無効化する更新を最大5秒で試みる |
| GitHubからの VOICEVOX runtime 取得 | 1 HTTPリクエストあたり180秒 | runtime取得をエラーで終了する |
| TCP監視クライアント | 接続後2秒 | 読み込み・メトリクス取得・応答書き込みを中断して接続を閉じる |

## ユーザー応答の期限

`timeout_millis` は rate limit を通過した後、チャンネル名の取得、添付URLの更新、進捗メッセージの作成、モデル生成を通した単一の期限です。準備に時間を使うと、その分だけモデル生成に使える時間が短くなります。添付URL更新だけは15秒で先に打ち切ります。更新が間に合わなくても古いDiscord画像URLをモデルAPIへ渡さず、該当画像を除いて残りの会話を処理します。

生成後の本文や生成画像の送信は別の30秒期限です。生成が成功してもDiscordへの送信に失敗する場合があり、複数メッセージの一部だけが届くことがあります。thinking表示は送信完了後に削除します。失敗表示と削除はそれぞれ最大5秒のbest effortです。

## 上限の読み方

Discord HTTPクライアントの30秒はHTTPリクエスト単位です。Discordのrate limit待ちや、複数リクエストを続けて行う上位処理の合計時間はこの値だけでは決まりません。そのため応答生成、添付URL更新、最終送信、component操作、TCP監視にはそれぞれ処理単位の上限を設けています。

タイムアウトは外部サービスで開始済みの処理を取り消した保証にはなりません。特に複数メッセージを送る途中で期限を迎えると、一部の送信だけが完了している場合があります。応答タイムアウト時は後続処理を待たずにログを残し、利用者へのエラー表示を短時間だけ試みます。
